# Liubai 26.x 测试指南

本文用于测试 26.x 版本的留白（Liubai）客户端优化功能。测试时请为每个 Minecraft 版本使用独立实例和独立 `mods`、`config` 目录，避免旧版本配置或其他模组干扰结果。

## 当前构建产物

| 平台 | 文件 | 状态 |

| Fabric 26.2 | 无 JAR | 当前 Fabric Loom 缺少 26.2 可用 mappings，待 mappings 发布后构建 |

26.x 需要 Java 25。启动器中应选择 64 位 Java 25，并确认日志中没有“requires Java 25”错误。

## 基础安装

1. 为目标版本创建全新客户端实例。
2. 安装对应版本的 NeoForge Loader。
3. 将对应 JAR 放入 `mods`，不要同时放入另一个 26.x 或旧 Minecraft 版本的留白 JAR。
4. 首次启动后关闭游戏，确认生成了留白配置文件；NeoForge 配置通常位于 `config/liubai-client.toml`。
5. 重新启动并进入一个测试世界。建议使用创造模式，准备玻璃墙、石墙、箱子、盔甲架、掉落物、粒子源和带名称的实体。

## 配置项测试

通过 NeoForge 配置界面或配置文件检查以下项目：

- `spectatorMode=false`：默认值。进入观察者模式后，实体、方块实体、阴影、名称牌和粒子不应被留白主动剔除。
- `spectatorMode=true`：允许观察者模式使用全部剔除策略。
- `entities=true`、`blockEntities=true`：分别控制实体和方块实体剔除。
- `occlusion=true`：启用完整实心遮挡检测。
- `occlusionMode=auto`：检测到 Entity Culling 时使用外部后端，否则使用内置后端。
- `showHud=true`：显示左上角调试 HUD；完成性能测试后恢复为 `false`。

修改配置后重启客户端，或通过配置界面保存后确认日志没有解析错误。将 `spectatorMode` 在 `false` 和 `true` 之间切换，确认配置会持久化。

## 观察者模式回归测试

1. 设置 `spectatorMode=false`，进入测试世界并切换为观察者模式。
2. 穿过石墙观察墙后的生物、箱子、盔甲架和粒子。它们应继续正常显示，不应因为留白策略消失。
3. 观察实体阴影和名称牌；它们也应保持渲染。
4. 设置 `spectatorMode=true` 后重复移动。远处、被完整墙体遮挡或低优先级对象可以被跳过，但移动镜头后应及时恢复。
5. 在观察者模式和生存/创造模式之间往返切换，确认不会出现永久消失的实体、黑色方块实体或残留名称牌。

## 遮挡剔除正确性测试

使用以下场景逐项验证“宁可多渲染，不错误剔除”：

1. 将生物放在无遮挡、半遮挡和完整石墙后，分别从正面、侧面和斜角观察。
2. 移动或拆除墙体，确认对象在可见后恢复渲染。
3. 用玻璃、树叶、栅栏、台阶和水替换石墙；这些非完整实心遮挡不应导致对象永久消失。
4. 让实体快速移动、传送或跨区块，确认缓存失效后会重新检测。
5. 将 `occludedConfirmations` 临时设为 `1` 观察激进效果，再恢复默认值 `2`。测试结束后不要保留极端调试值。

## 屏幕空间、距离和密度策略

打开调试 HUD，记录未启用留白时的平均帧时间，然后逐项启用：

- 将 `minimumProjectedRadius` 设为较大值，观察远处小实体是否减少；靠近对象后应恢复。
- 增大 `safeDistance`，确认摄像机附近对象不因屏幕尺寸或密度策略被跳过。
- 在大量生物、掉落物和粒子场景中观察 `entitiesDensityLimited`、`particlesSkipped` 等计数是否变化。
- 快速转动镜头和移动玩家，确认画面不会闪烁、拖影或出现一帧以上的错误空洞。

## 方块实体和特殊渲染器

准备箱子、末影箱、告示牌、熔炉、旗帜、盔甲架以及安装了特殊渲染器的模组方块：

- 方块实体在完整墙后可以被剔除；打开、交互或移除墙体后必须恢复。
- 动态方块实体、动画方块和第三方特殊边界应保持可见，不得崩溃。
- 出现异常时，将对应命名空间加入 `disabledNamespaces`，重启后确认该命名空间不再被剔除。

## 联动模组测试

在单独实例中逐个加入可用版本的 Entity Culling、Iris、Create/Flywheel、Valkyrien Skies、Sable 或 Create Aeronautics：

1. 启动并查看日志，确认 Liubai 对未知或不兼容版本采取安全放行，而不是阻止启动。
2. 使用 Create 机械、Flywheel 视觉对象和移动结构观察远处更新；确认不会出现错位、冻结或消失。
3. 使用 Iris 着色器（如有对应 26.x 版本）观察阴影和透明物体；切换着色器时不应崩溃。
4. 关闭联动模组后再次启动，确认 Liubai 仍能使用内置后端。

## 性能对比方法

每次只改变一个变量，并记录：平均 FPS、1% low、平均帧时间、P95/P99 帧时间、内存占用和 HUD 中的剔除计数。建议使用同一世界、同一视角、同一渲染距离，连续记录 60 秒；先预热 30 秒再取样。比较以下四组：

1. Liubai 关闭；
2. 仅实体/方块实体剔除；
3. 加入遮挡检测；
4. 加入屏幕空间、粒子和 Flywheel 策略。

如果平均 FPS 提高但 P99 或卡顿恶化，应降低 `checksPerFrame` 或 `budgetMicros`，优先保证帧时间稳定。

## 崩溃与日志收集

出现崩溃、渲染错误或对象消失时，保留以下文件和信息：

- `logs/latest.log`、崩溃报告和对应实例的 `config/liubai-client.toml`；
- Minecraft、NeoForge、Java、显卡驱动和已安装模组列表；
- 触发问题的配置项、世界种子/坐标和最小复现步骤；
- 是否启用观察者模式、Iris 着色器或第三方渲染模组。

测试完成后恢复默认配置，删除仅用于调试的临时模组，并重新验证一次纯净实例启动。

## 通过标准

版本可视为通过的最低标准是：客户端正常启动；默认 `spectatorMode=false` 行为正确；墙体拆除、镜头移动和模式切换后对象及时恢复；未知联动版本安全放行；连续 60 秒测试期间无崩溃、严重闪烁、永久黑块或实体丢失；并且性能数据能够说明启用策略的收益和代价。
